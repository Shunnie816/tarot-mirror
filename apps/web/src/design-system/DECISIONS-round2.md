# 判断の記録 — 第2ラウンド（盤面と4画面）

`claude design` の出力をそのまま残したもの。実装で確かめた結果は末尾に追記してある。

## 1. カードの配置と読み物の関係づけ — 「同居、ただし別レイヤー」

盤面と読み物は**同じ画面に縦に積む**が、**幅の制約を共有しない**。

- 盤面は `--measure-board`（最大 58rem）。カードは横に並ぶので幅が要る。
- 読み物は `--measure-reading`（38em ≒ 全角37〜38字）のまま。**1カラムを維持**し、盤面の幅に引きずられない。
- 両者は同じ中央軸に載る。盤面のほうが広いので、読み物は盤面の中に落ちる形になる。

**往復の仕組み**: 盤面のカードは押せる。押すとそのカードの本文へスクロールする（`prefers-reduced-motion` では即時ジャンプ）。
「あなたと相手のカードは…」という本文を読んだあと、盤面に目を戻せば上下の鏡が見える。
逆に盤面で気になったカードから本文に入れる。**カードごとに本文を横に並べる案は採らなかった** — 38字 × 3 = 読めない幅になり、前回の唯一の制約と正面衝突するため。

3枚スプレッドの「横の流れ」は、盤面の1行（これまで→いま→この先）が担う。本文は縦のままでよい。
横の流れを取り戻す場所と、じっくり読む場所を分けたということ。

## 2. 段階開示の単位 = 群（8回問題の答え）

**単位を「1枚」から「群」に変えた**。妥当だと判断した理由は、エンジンが群で構造化していて、
本文の横断的な観察も群を参照しているから。開示単位がデータ構造と一致する。

- 8枚: あなた（開いた状態）→「「相手」の三枚をひらく」→「「二人のあいだ」の二枚をひらく」→「全体をとおして読む」＝ **操作3回**
- 3枚: 1群なので最初から3枚とも開く →「全体をとおして読む」＝ **操作1回**
- 1枚: 群も1つ、横断的な観察も存在しないので「締めの言葉を読む」＝ **操作1回**

副作用として群が視覚的に立った。群の切れ目は **上に 1px の実線（border-strong）＋ ゴシックの群名（藍）＋ 明朝の細い一文**で示す。
ポジション名は `あなた・これまで` のままだが、群見出しがあるので群名の反復が読み飛ばせる。

盤面の側でも群を見せる: あなたの行と相手の行のあいだに「鏡」と書いたハーフライン、
「二人のあいだ」は脇（右）に別ブロックとして置き、群ラベルだけテラコッタにして「どちらにも属さない」ことを示す。

ドロー画面も同じ単位。**シャッフル演出なし**。「順番はもう決まっています」と明示して、引き当てる期待を作らない。
ボタンを押すと群の3枚が 560ms・150ms ずつずれて置かれる。8枚でも操作3回。

## 3. 盤面をモバイルでどう成立させたか

**メディアクエリを使っていない。** 盤面は2階層の flex-wrap だけで組んだ。

- カード = `flex:1 1 0; min-width:0` の等分。行のなかの3枚は**幅がいくらでも必ず3枚横並び**になり、狭いと縮む。
  `--space-tile-gap: 10px` と `--text-card-tile` の下限（16px）で、320px 幅でも3枚が成立する。
  カード名は最長でも4文字程度（文字だけなので画像枠のような最小幅がない）。これが画像を使えない制約の副産物。
- 群の並び = 外側 flex-wrap。左ブロック（あなた／相手）は `flex:1 1 20rem`、脇ブロック（二人のあいだ）は `flex:1 1 13rem`。
  PC では右に並び、狭い画面では自然に下へ回り込む。**上下の鏡は幅に関係なく保たれる**（常に行として積まれている）。
- 脇の2枚は `flex:1 1 9rem`。PC の細い脇ブロックでは縦に2枚、モバイルの全幅では横に2枚に自動で切り替わる。

## 4. 逆位置の表し方（文字だけ）

カードの向きを、**罫線の位置**で示す。正位置はカードの下辺に 1px（border-strong）、逆位置は上辺に 1px（テラコッタ）。
物理カードの上下が入れ替わることの写しで、盤面を引きで見たときに逆位置の分布が見える。
カード名を 180° 回すのは読めなくなるので採らなかった。本文側では従来どおり「正位置／逆位置」の枠つきラベルを併記する。

> **追記（Issue #21 / #34、カード画像の導入後）**
> 絵が入ったので、**絵のほうを 180° 回す**ようになった。回すものが文字ではなくなり、
> 「読めなくなる」という理由が消えたため。文字は回さないままで、これは変えていない。
>
> 罫線も残した。絵が届く前・読み込みに失敗したとき・画像を持たないデッキでは、
> 向きが分かる手がかりがこれしか無い。「引きで見たときに逆位置の分布が見える」という
> 効き目も、細い線のほうが担っている（絵は1枚ずつ見るもので、面では読めない）。

## 5. スプレッド選択・質問入力

- スプレッド選択は**盤面の形そのものを選択肢**にした（空の盤面をそのまま置く）。枚数はラベルにしていない。
  説明文は「考える範囲の違い」で書き、8枚には「読む量は多くなります」とコストを書いた。上位プランに見せない。
- 質問入力は自由入力なので**入力文字を明朝**にした（利用者の言葉＝読み物側）。ラベル・ボタンはゴシック。
  「この問いで進む」（塗り）と「問いを書かずに進む」（枠線）を**同じ大きさで横並び**に置いた。スキップリンクにすると
  「書かないのは手抜き」という含みが出るため。文字数カウンタは置かない。

## 6. 明朝／ゴシックの境界（前回の規則を新カテゴリへ拡張）

- 明朝: 解釈本文、全体をとおして、問い（リスト）、締め、カード名（盤面のカード名も）、画面タイトル、利用者の入力文、
  各画面の導入文・状態を伝える一文（「すべて置きました。」）
- ゴシック: ポジション名・群名・正逆ラベル、盤面のポジションラベル、ボタン、フィールドラベル、注記、画面ナビ

盤面のカード名を明朝にしたのは、盤面が「UIの部品」ではなく**象徴が置かれた場**だから。
一方ポジションラベルは位置の名前なのでゴシックのまま。境界は前回と同じ「読むもの／位置を示すもの」で引けている。

| 主張 | 実測 |

| 320px でも3枚横並びが成立する | 成立。各79px・高さ134px・横スクロールなし |
| メディアクエリなしで PC→モバイルが通る | 通った。盤面・読み物とも1行も追加していない |

文字だけのカードなので破綻はしていない。
